# Codex: brief, budget, Goal and delivery

## Ask focused questions

Read the conversation and authorized project files. Use the host's question tool when available, otherwise ask in chat. Ask 1–3 questions per round, prefill known facts, suggest useful options and accept creative delegation. Cover audience, inputs, devices, output and unresolved constraints. Continue independent work while an answer is pending; wait for required approval before the dependent action.

## Agree the budget

Before substantial work, resolve the user's preferred limit: a deadline/timebox, maximum paid spend, explicit token cap or remaining account-allowance floor. Keep these quantities separate. Use an available account-usage tool to measure the relevant window; otherwise agree a measurable alternative. Record budget and exclusions in the checkpoint.

Obtain explicit authorization for paid services, credits/resets, new keys, account changes and model changes. Reserve time for testing and packaging. At a limit, save a checkpoint and report the next action; ask before increasing the cap. Test a representative sample before batch generation. After the same failure twice, revise the approach or report the blocker.

## Goal mode

Ask whether the user wants Goal mode or a bounded work session. Activate Goal only on explicit request with a currently available tool, preserving existing goals. If unavailable, use the normal session and project checkpoints.

Agree a testable objective and relevant acceptance criteria, for example:

“Build a private offline photo pop-up game from approved inputs. Verify opening, controls, completion, replay, responsive layout, audio/text clues and recovery; deliver HTML, source and validation report within the agreed budget.”

Use the host's current Goal lifecycle controls. Keep deadlines, percentage floors and numeric token caps in their original units. Include only checks relevant to the intended deliverable.

## Build and resume

Use an isolated output directory, preserve originals and follow workspace instructions. Build a representative scene, then expand. Run the state/build tests and browser checks in implementation-qa.md; record results and pending checks in one validation report. Follow current platform rules when selecting execution or delegation routes.

Save brief, limits, asset provenance, decisions, results, pending inputs and next action. On restart inspect these and current files/processes before repeating work. Keep working records private. Deliver the playable result, source and report; use separately authorized routes for publication, third-party upload or installation.
