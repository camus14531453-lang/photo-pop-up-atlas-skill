# Build a photo pop-up game

Own the work from brief to playable delivery: prepare assets, build the game, verify it and provide the result. Coordinate tools and files directly so the user can stay focused on creative choices. The package includes a neutral 3D starter that can be adapted to the project.

## Working conversation

Lead with the current action or useful result and continue authorized work. Gather necessary background through the platform's intake flow, reuse answers already given, and make reasonable creative defaults. Keep capability discovery, routine checks and troubleshooting in the working process; bring the user a specific decision only when it affects the next step.

When a missing tool, file or approval actually blocks an action, name that action and the concrete next step in one sentence, then continue independent work. Explain a limitation once at the decision it changes. Keep test coverage and remaining validation in the report, and summarize only what matters to using the result. Report observed outcomes accurately.

## 1. Establish the brief

Read [intake.md](references/intake.md). Prefill known answers and collect the remaining background in one compact questionnaire. Accept “you decide,” record assumptions and proceed. Ask later for blocking inputs or changed scope.

Read [execution.md](references/execution.md) to select the workspace, verify tools and maintain project checkpoints. Record audience, source material, fidelity requirements, devices, rendering approach, play length and delivery scope.

## 2. Design the interaction

Derive the player's objective, actions, rules, feedback and completion from the material. Examples include rebuilding a scene from photo clues, identifying places by sound, or following a route. Make discoveries change game state and contribute to the objective.

Choose full 3D geometry, paper cut-outs in a 3D scene, or DOM/CSS depth to match the brief. Plan an accessible view with equivalent controls and clues. Set map layout, pages, narrative, typography and sound for this project.

## 3. Prepare assets

Follow [assets-audio.md](references/assets-audio.md) for photo references, image-generation/editing calls, cut-out inspection, audio preparation, provenance and permissions. Preserve important identity, text, geography and recorded meaning. Store project material separately from this reusable skill.

## 4. Build and expand

Use [starter.md](references/starter.md) for the offline builder and configuration. For linked maps, standing locations, tasks, audio and cross-page progress, read [atlas.md](references/atlas.md).

Complete one representative scene with controls, sound, state, completion, replay and recovery, then expand. Default to static client-side files with local assets. Keep dependencies and optional services within the agreed access and budget. Preserve working behavior during revisions and update checkpoints.

## 5. Verify and deliver

Follow [implementation-qa.md](references/implementation-qa.md). Test the objective, replay, responsive layout, keyboard access, media and recovery in the intended environment. Keep coverage, evidence and remaining checks together in the project validation report. Resolve blockers where possible and record the next action for anything outstanding.

Follow [public-release.md](references/public-release.md) to package approved files. Deliver the playable result, source, controls, credits and validation report. Publish, upload or install only within the user's authorized scope.
